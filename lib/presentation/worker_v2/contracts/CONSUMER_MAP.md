## Frozen identifiers and routing

`WorkerDestination` catalog (unchanged from V1): `today`, `jobs`, `schedule`, `earnings`, `account`, `login`, `readiness`, `offer`, `mission`, `visit_scope`, `earning_detail`, `deposit_account`, `deposit_ledger`, `disputes`, `dispute_thread`, `notifications`, `support`, `sos`, `profile_edit`, `work_areas`, `working_hours`, `start_location`, `reviews`, `language`, `privacy`, `terms`. `RouteOrigin` is `today`, `jobs`, `schedule`, `notification`, `profile`, `mission`, `finance`, `system`.

Five native tab IDs/indexes: Today=0, Jobs=1, Schedule=2, Earnings=3, Account=4. Legacy MainScreen indexes translate 0→0, 1→2, 2→1, 3→4; legacy status filter is retained. `/login`→login; `/main`→requested translated tab; `/orderdetails`/`cleaning_booking_details`→mission; `/emergencysos`→sos; `/transactiondetails`→dispute_thread; `/transactionhistory`→deposit_ledger; `/notifications`→notifications. Legacy `/updateprofile`, `/workerreviews`, `/workingtime` and profile/areas/hours aliases map to S04 replacements. Earning detail requires source-qualified `entityId`, dispute thread requires dispute `entityId`; neither changes its meaning based on alias. `RouteResolution.unavailable` carries localizable `target_unknown` or `target_invalid` and a destination can never silently select a sibling visit.

## Typed invariants

- `WorkerSessionContext.generation` is mandatory; runtime invalidations and cache keys must match current user, worker, generation, contract `V2` and query key. New login/account switch/401 must clear cached data before exposing new identity.
- `WorkScope.sessionId` is nullable only when the server supports legacy booking scope; null is not permission to navigate to another visit.
- Reads use `ReadSuccess` with `fetchedAt`/freshness or `ReadFailure` with typed 401/403/404/409/422/network/server failure. UI `LoadState` can retain stale content after refresh failure but must not fabricate the initial content.
- Commands use `confirmed`, `rejected`, `outcomeUnknown`. Timeout after submission is outcome unknown, and clients must refetch before retry; no automatic replay. Supervisor-managed visits can permit attendance but deny execution.
- `WorkerAction` allows only canonical server-authorized actions. Blocked reasons are sanitized enum strings. S03 discards unknown action strings; it never adds an enabled action from a screen label.
- `MoneyValue` validates exact decimal strings and 3-letter uppercase currency; no `double` arithmetic, cross-currency sum or null-to-zero coercion. S02/S03 must not recalculate frozen amounts.
- Business filters use `DateRange` Asia/Damascus inclusive dates and `PageQuery` pagination. Offer/booking/deposit/dispute query keys JSON-encode structured filter tuples to prevent arbitrary delimiter collisions. UTC instants for canonical visit bounds remain nullable when ambiguous. Caches store sanitized assigned summaries max 24h, no contact/GPS/code/private media/ledger.

V2 changes route identity rejection semantics and the typed service-line, reservation and extension-decision seams. The catalog retains all 17 existing behavior scenarios; typed identity regression fixtures exercise the new read-to-command paths. Fixture data is synthetic for consumer tests and cannot replace real authenticated API/DB evidence. `VERSION` and `FIXTURE_HASHES.json` freeze these samples. Feature lanes may request a contract amendment through `reports/<ID>/requests/CR-<number>.md`; only S00 changes these files.

S03 migration required before WR-D: map authorized specialized-service records to `MissionServiceLineView(scope, lineId, label, status, allowedActions)` without collapsing duplicate labels; map equipment ID and reservation ID into separate `InventoryItemView` fields and suppress custody actions if reservation ID is missing; set `DecisionView.extensionFamily` only when the wire record is authoritatively identified as `CleaningTimeWarning` or `CleaningOpenTimeExtension`; serialize `ExtensionDecisionCommand.family` to the existing family-specific route and preserve optional `additionalMinutes` only for accepted fixed warnings. S03 must acknowledge V2 and cannot infer family from a colliding numeric ID or invent a lifecycle.
